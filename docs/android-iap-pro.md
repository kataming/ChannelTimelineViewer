# Android 版の課金（Pro 買い切り）— 実装と Play Console 設定

Channel Timeline Viewer Android 版の収益化は **アプリ本体は無料＋Pro の買い切り（One-time product）** とする。
サブスクリプションは使わない。アフィリエイト・紹介報酬・成果報酬の仕組みも入れない。

- 無料: **保存チャンネル1件**。その1件の中では主要機能を**一切制限しない**
- Pro: **複数チャンネル保存**と、チャンネルごとの進捗管理・保存チャンネル一覧の管理

「視聴者さんが貴チャンネルを無料で保存できる」と YouTuber に説明できることが、この設計の中心価値。

---

## 1. 無料でできること / Pro で解放されること

| 機能 | 無料 | Pro |
| --- | --- | --- |
| チャンネル保存 | **1件** | 複数 |
| 古い順 / 新しい順の並べ替え | ○ | ○ |
| 視聴済み管理 | ○ | ○ |
| 続きから再生 | ○ | ○ |
| 移動ボタン | ○ | ○ |
| メモ | ○ | ○ |
| 進捗表示 | ○ | ○ |
| 公式埋め込みプレイヤーでの再生 | ○ | ○ |
| 複数チャンネルごとの進捗管理 | — | ○ |
| 保存チャンネル一覧の管理 | — | ○ |
| 今後追加する上位の管理機能 | — | ○ |

制限するのは **同時に保存できるチャンネル数だけ**。視聴体験そのものは削らない。

## 2. アプリ側の実装

| 役割 | ファイル |
| --- | --- |
| 保存件数の判定（純ロジック・テスト対象） | `android/app/src/main/java/.../billing/ChannelSlotPolicy.kt` |
| Pro 所有状態の保持 | `.../billing/ProEntitlementStore.kt` |
| Google Play Billing の入口 | `.../billing/ProBillingManager.kt` |
| 購入画面 | `.../ui/ProScreen.kt` |
| 2件目保存時の案内ダイアログ・Pro への入口 | `.../ui/ChannelInputScreen.kt` |
| 上限判定の呼び出し | `.../viewmodel/ChannelInputViewModel.kt` |
| テスト | `android/app/src/test/java/.../ProEntitlementTest.kt` |

決めごと:

- **Play Billing Library 9.1.0**（`com.android.billingclient:billing`）。
  2026-08-31 以降は新規アプリ・更新とも **8 以降が必須**なので 9 系を入れている（9.x は compileSdk 35 が要る＝本アプリは 35）。
- 商品は `pro_unlock` の1つだけ。**価格はコードに持たない**。Play が返す `formattedPrice` をそのまま表示するので、
  Play Console 側で値上げしてもアプリの更新は要らない。
- 購入が確認できたら **必ず `acknowledge` する**。3日以内に確認しないと Google が自動返金して購入が消える。
  消費（consume）はしない＝買い切りとして所有し続ける（Apple でいう Non-consumable と同じ扱い）。
- 購入状態の確認は **起動時（`start`）・前面復帰時（`onResume` → `refresh`）・購入画面表示時**の3か所。
- 端末内には Pro フラグの**写し**だけを持つ。正は常に Play 側。
  **Play への問い合わせが成功して「購入なし」だったときだけ** false に落とす
  （圏外・Play 未接続で Pro が消えないようにするため）。
- 購入失敗・キャンセル・保留・復元失敗のどれでも落とさない。UI にメッセージを出すだけ。
  - キャンセル（`USER_CANCELED`）は何も出さない
  - 保留（`PENDING`）は「確認待ち。完了すると自動で有効になります」
  - 所有済み（`ITEM_ALREADY_OWNED`）は問い合わせ直して Pro を復元する

### 2件目を保存しようとしたときの挙動

1. 保存上限に当たると**開かずに**案内ダイアログを出す
2. 選べるのは3つ: **Proにする** / **入れ替える** / **キャンセル**
3. 「入れ替える」を選ぶと、保存中のチャンネルを外して新しいチャンネルを保存する
   - **視聴済み・進捗・メモ・再生位置は消さない**。元のチャンネルを保存し直せば続きから見られる
4. Pro を買うと、保留していたチャンネルがそのまま開く

### 既存データ（この課金より前から複数保存している人）の扱い

**勝手に消さない。** 保存済みのチャンネルは Pro でなくても開ける。増やすときだけ上限がかかる。
本人が「入れ替える」を選んだときに限り、空きを作るぶんだけ（最後に開いたのが古い方から）外す。

## 3. Play Console で人が行う設定

API では設定できないので、Play Console の画面で行う。

### 3-1. アプリ本体を無料にする

**収益化 → アプリの価格設定**（`.../app/<appId>/pricing`）で **無料** にする。

> **一方通行**。無料にすると、その後この アプリを本体有料に戻すことはできない。
> 今回はその前提で「本体無料＋Pro 買い切り」に決めている。

### 3-2. アプリ内アイテムを作る

**収益化 → 商品 → アプリ内アイテム**（`.../app/<appId>/managed-products`）→ **商品を作成**

| 項目 | 値 |
| --- | --- |
| 商品ID | `pro_unlock` （**作成後は変更できない**。アプリのコードと一致させる） |
| 商品タイプ | 1回限りの購入（One-time product） |
| 消費のしかた | **消費しない**（買い切り。Apple の Non-consumable に相当） |
| 商品名 | `Channel Timeline Viewer Pro` |
| 説明 | 複数チャンネル保存を買い切りで解放します。サブスクリプションではありません。 |
| 価格 | 初期は **$4.99 相当**（ローンチ価格）。将来 $9.99 相当へ変更する前提 |
| ステータス | **有効（アクティブ）** |

- 商品を「有効」にしないと、アプリ側で価格が取得できず購入ボタンが押せない。
- 各国の価格は基準価格から自動換算される。7言語の対象国はすべて自動で入る。
- **値上げしてもアプリの更新は不要**（価格はコードに持っていないため）。

### 3-3. 商品名・説明の多言語（任意）

アプリ内アイテムの名前と説明は Play Console 側で言語ごとに入れられる。
アプリ内の購入画面は**アプリ側の7言語文言**（`Localization/strings.json` の `pro.*`）を使うので、
Play Console 側は日本語・英語だけでも実害はない。

### 3-4. プロモーションコード（YouTuber 向け）

**収益化 → プロモーション → プロモーションコードを作成**

- 対象に `pro_unlock` を選び、必要な枚数だけ発行する
- YouTuber 本人へ Pro を無償提供したいときに使う
- **アプリ内にコード発行・引き換えの機能は作らない**（Play Console の運用として行う）
- 発行枚数には四半期ごとの上限がある。不特定多数へのばらまきには使えない

### 3-5. 審査メモに書くこと

App content / リリースノートの「審査担当者への説明」に次を入れておく。

```
本アプリは無料で利用できます。無料の状態でも、保存した1チャンネル内の全機能
（古い順/新しい順の並べ替え、視聴済み管理、続きから再生、メモ、進捗表示、
公式埋め込みプレイヤーでの再生）が制限なく使えます。

アプリ内課金は「pro_unlock」1つのみで、買い切り（One-time product）です。
サブスクリプションではありません。購入すると複数チャンネルの保存が解放されます。

動画の再生は YouTube 公式の IFrame Player を WKWebView/WebView で表示する方式のみで、
ダウンロード・独自プレイヤー・広告回避・バックグラウンド再生は実装していません。
```

> 「アプリ内購入あり」の申告が必要になる。**データセーフティは「データを収集していません」のままでよい**
> （購入処理は Google Play が行い、当方のサーバーは介在しない）。

## 4. テスト購入のしかた

実際に課金せずに購入フローを試せる。**AAB を内部テストトラックに上げてから**でないと動かない
（ローカルの debug ビルドでは商品情報を取得できない）。

1. **ライセンステスターを登録する**
   Play Console → 左下 **設定 → ライセンステスト**（デベロッパーアカウント単位）
   → テストに使う Google アカウントを追加 → ライセンス応答は `RESPOND_NORMALLY`
2. **内部テストのテスターに、同じアカウントを入れる**
   テスト → 内部テスト → テスター
3. 端末にその Google アカウントでログインし、**内部テストのリンクからインストールする**
   （ローカルの adb install ではなく、Play 経由で入れること。ライセンス判定が効かないため）
4. アプリ → Pro 画面 → 購入
   - 支払い画面に **「テスト カード（常に承認）」** が出れば正常。**実際の請求は発生しない**
   - 「テスト カード（常に拒否）」を選べば失敗時の挙動を確認できる
5. 買い直したいときは、Play ストアアプリ → メニュー → お支払いと定期購入 → 予算と履歴 から
   テスト購入を返金・取り消しするか、ライセンステスターの購入は数分で自動的に消える

確認する項目:

- [ ] 購入前は保存チャンネル2件目で案内が出る
- [ ] 「入れ替える」で 1件目が外れて 2件目が開ける。視聴済み・進捗が残っている
- [ ] 購入後は2件以上保存できる
- [ ] アプリを削除して入れ直しても、同じ Google アカウントなら Pro が復元される
- [ ] 機内モードで起動しても Pro が消えない
- [ ] 購入をキャンセルしてもエラーが出ない・落ちない
- [ ] 「購入を復元」で、購入がないアカウントでは「見つかりませんでした」と出る

## 5. iOS 版との関係

iOS 版も同じ「無料＋Pro 買い切り」に揃える方針。文言は
`Localization/strings.json` の `pro.*` を両方で共有しているので、iOS 側は StoreKit の実装を足すだけでよい。

- App Store 側は **Non-Consumable** の App 内課金として作る（商品ID は `pro_unlock` に揃える）
- iOS は「無料 → 有料」への変更が可能なので、本体価格の扱いは Android と違って一方通行ではない
