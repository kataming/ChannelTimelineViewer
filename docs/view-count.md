# 視聴回数の表示と「人気順」（iOS 1.4.1 / Android 1.17・2026-10-04）

ユーザーの依頼:
- 一覧画面と再生画面で、`[2018年4月15日][10万回視聴]` の並びで視聴回数を出す
- 一覧の右上メニューの並び順に、古い順・新しい順に続けて **人気順** を足す

## 見た目
- 一覧の行: `2015/03/05 · 277万回視聴`（日付の書式は今までどおり）
- 再生画面: `2015年3月5日 · 277万回視聴（1 / 245）`（一覧の中での位置は今までどおり最後）
- 数は短い表記（日本語「277万」、英語「2.7M」）。表示言語に合わせる
  （iOS `formatted(.number.notation(.compactName))`、Android `CompactDecimalFormat`）
- 視聴回数が取れていない動画は日付だけ（「· 0回視聴」とは出さない）
- 文言は `video.viewCount.format`（%@回視聴）と `list.sort.popular`（人気順）・35言語

## 人気順の並べ方（iOS / Android で同じ）
1. 視聴回数の多い順
2. 視聴回数が分からない動画（非公開・未取得）は最後
3. 同じ回数・分からない同士は古い順

「次に見る」は並び順に関係なく、これまでどおり**古い順で最初の未視聴**。

## 取り方（YouTube Data API）
- `videos.list?part=statistics` を **50 本ずつ**（1 回 = quota 1）。スクレイピングはしない
- いつ取るか:
  - 一覧を全件取り直したとき（初回・全件再読み込み）→ 全件
  - 新着が見つかったとき → 新着の分だけ
  - 保存済みの一覧を開いたとき、前回まとめて取ってから **7 日以上**たっていれば → 全件
- 失敗しても一覧はそのまま使える（表に出さない）
- 取った回数は一覧の保存（キャッシュ）に一緒に入れる。まとめて取った日時は
  iOS `VideoListCache.Entry.statsUpdatedAt` / Android `VideoListCache.Entry.statsUpdatedAtEpochSeconds`
- 1.4.1 / 1.17 より前の保存には視聴回数が無い → 開いたときに取り直す（古い保存もそのまま読める）

### 7 日にしている理由
- YouTube API の規約で、保存した API のデータは **30 日以内に取り直す（または消す）** 必要がある
- 一方で全件の取り直しは本数 ÷ 50 の quota を使う（5,000 本のチャンネルで 100）。
  毎回取り直すと quota を大きく使うので、規約の範囲で間隔を空けた
- 変えるときは iOS `VideoListViewModel.viewCountRefreshInterval` / Android `VIEW_COUNT_REFRESH_SECONDS` の両方

## 対象外
- 公式サイトの Web 体験版（`site/`）は変えていない
- ストアの説明文の機能一覧には足していない
